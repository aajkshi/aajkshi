## 來源取得方式與先前問題

透過可執行 JavaScript 的瀏覽器實際取得線上升級頁的 FAQ 可見文字（不是只看官網靜態 HTML），確認「自行升級」頁目前的 FAQ **共 6 題**。先前的 GitHub 展示版自行增補了「機型辨識」、「記憶卡無法觸發更新」及其他 FAQ，導致與官網當下顯示的升級專區完全不同。本次撤回這些擅自增補，恢復官網原本的題目、順序與答覆。

## 官網升級頁現行 FAQ 題目

1. 升級 Android 16 會清除資料嗎？
2. 已過保也可以自行升級嗎？
3. 需要先安裝過渡版本嗎？
4. 有使用飛鼠，應該先更新哪一個？
5. 更新超過 30 分鐘仍未完成怎麼辦？
6. 更新完成並重置後，切換中文需要的密碼在哪裡？

修正後 GitHub 版依照以上順序，原題目 3 依已核准的本站用語改為「需要先安裝指定升級韌體嗎？」；Touch 例外依已確認的單次更新規則說明。其他主要答案以現行官網升級頁所示內容為底，其中：

- **第 6 題密碼**：官網指出中文密碼在保固卡上。保固卡遺失時，拍攝**主機外觀**與「設定」頁面最下方（或「關於」內）的 **IMEI 資訊**，傳給官方 LINE 客服查詢。本站已恢復該答案，不再自行改成泛用的「提供購買資訊」。
- **第 5 題逾時**：維持已確認、也與官網一致的保持供電及提供機型、韌體版本、畫面和主機燈號給 LINE 客服的說明。
- **第 3 題韌體**：官方目前仍使用「過渡版本」，本站因使用者此前要求稱為「指定升級韌體」，但不改原定機型檔案及 Touch 單階段特性。

官網的「過保免費任務與運費怎麼計算？」「需要準備哪些資料？如何包裝寄送？」「主機送達後，多久能完成升級？」仍作為寄回升級面板內的三個問答，不額外混入自行升級的六題 FAQ；「更新後無畫面／BMW 連線」保留在機型升級教學區。

## 技術修正

- 同事展示、純前台、前後台正式前台及獨立 v6 四份 HTML 都已同步改為 **6 題靜態 HTML FAQ**，即使 JS 未執行也會有題目與可展開答案。

- 已將寄回三個問答移回寄回面板、機型連線排除提示移回機型教學，避免把不同內容混成 14 題。
- 不變項目：MG 單一警示品牌、無下載前確認彈窗、Touch 一次更新、指定升級韌體用語、30 分鐘客服文案、客服 LINE 申請順序。

## 本次核對邊界

已透過執行官網 JavaScript 的網頁內容擷取取得當前 FAQ 文字；現行官網對不同機型／模式的動態呈現仍可能因操作狀態而變化。本站以取得的官網**自行升級預設狀態六題**及**寄回升級頁面原有三個問答**為基礎，不宣稱還原每一種機型狀態下的全部微小差異。

本次所執行的程式與 HTML 靜態一致性檢查不等同對正式主機或跨裝置顯示完成實機驗收。正式上線前仍須由網頁公司以瀏覽器逐項驗收。
